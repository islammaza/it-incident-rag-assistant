# Nginx Access and Error Logs

Nginx writes access logs for requests and error logs for processing and upstream failures. The access log helps establish the request method, path, response status, and timing. The error log provides details such as failed upstream connections, invalid configuration, permission problems, and protocol errors.

When investigating an HTTP incident, correlate the client-visible status with the Nginx error log and the upstream application's log using a narrow time window. Record the hostname, route, status, and relevant error class without copying credentials, tokens, or private request bodies.

## Useful questions

- Did the request reach the expected `server_name` block?
- Is the status generated by Nginx or returned by the upstream?
- Does the error name an upstream host and port?
- Are failures limited to one route, method, or client network?
- Did the incident begin after a reload, deployment, or certificate change?

Log rotation and retention matter on busy systems. A missing current log may indicate a path, permission, rotation, or disk-space problem. Validate configuration and file ownership before changing logging broadly.
